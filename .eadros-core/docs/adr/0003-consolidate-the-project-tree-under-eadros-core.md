# ADR-0003: Consolidate the project tree under `.eadros-core/`

- **Status:** Accepted
- **Date:** 2026-07-29
- **Deciders:** Maintainer
- **Related:** Supersedes ADR-0002 (layout only); RFC-0001 D6; AGENTS.md §4, §5

## Context

[ADR-0002](0002-adopt-cross-language-source-layout.md) fixed a repo-root layout —
`src/`, `docs/`, `.eadros-core/tools/` directly under the repository root — and declared it *normative for
every sibling project*. That decision optimizes for one property: that every project generated
by the same factory has an identical shape, so an agent's mental model transfers between them.

EADROS is not only a project generated by that factory. It is itself **a tool that vendors
itself into a user's repository**, and RFC-0001 **D6** made that containment binding: every
asset the product installs lives under `.eadros-core/`, the installation root — one directory
to install, to upgrade, to inspect and to remove. `/eadros upgrade` already treats that
directory as the migratable unit.

That gives the project two competing organizing principles, and the repo-root layout is the
weaker of the two here. It scatters the product across four root directories that a consumer
neither needs nor should see, while the thing the product actually ships is meant to be one
directory. The factory has already solved this for itself: EADOS keeps **all** its machinery
in `.eados-core/` and leaves only governance files above it, precisely so a repository that
vendors it can ignore the whole thing with a single line.

What forces the decision now is sequencing. The scaffold render has landed and nothing has
been built on top of it; moving the tree costs one commit today and grows more expensive with
every file added.

## Decision

**The project tree lives under `.eadros-core/`.** `src/`, `docs/` and `.eadros-core/tools/` move there; the
repository root keeps only governance files and the paths that external systems require.

```text
.
├── AGENTS.md · CLAUDE.md · GEMINI.md      # the agent contract and its adapters
├── README.md · LICENSE                    # GitHub surfaces these from the root
├── ROADMAP.md · CHANGELOG.md · SECURITY.md
├── package.json · tsconfig.json · .gitignore
├── .github/                               # workflows run ONLY from the repository root
├── .claude/                               # the host reads this exact path
└── .eadros-core/                          # the product — one vendorable directory
    ├── src/{main,test,bench}/typescript/dev/d4np/eadros/
    ├── docs/{adr,rfc,specs,patterns,workflow,journal,bugs,security,compliance,releases,benchmarks,development}/
    └── tools/consistency_lint.py
```

**What stays at the root is not a preference.** `.github/workflows/` is the only location
GitHub executes workflows from — placed elsewhere they do not fail, they silently never run.
`package.json` is required at the root by npm resolution, `npx` and publish. `.claude/commands/`
is read from a fixed path by the host. `README.md` and `LICENSE` are surfaced from the root by
GitHub. No ADR can move these, so the decision does not pretend to.

**ADR-0002 is superseded on the layout question only.** Its underlying rule — that source lives
in one declared tree, that code outside it is a review failure, and that the
`src/<phase>/<lang>/<group>/<slug>` shape is fixed — is retained verbatim. Only the tree's
parent changes, from the repository root to `.eadros-core/`.

**The tooling is path-stable by construction.** `.eadros-core/tools/consistency_lint.py` resolves its root as
`dirname(dirname(__file__))`, so moving it to `.eadros-core/tools/` re-points every `docs/**`
and `src/**` check at `.eadros-core/` with no path edits. Only the five reads of genuinely
root-level files — `README.md`, `ROADMAP.md`, `AGENTS.md` — need a second root, added as
`REPO_ROOT = dirname(ROOT)`. This mirrors `eados_lint.py`, which already splits `ROOT` from
`REPO_ROOT` for exactly this reason.

## Alternatives

| # | Alternative | Why rejected |
|---|---|---|
| A1 | **Keep ADR-0002's root layout** | Leaves the product scattered across four root directories while D6 commits to shipping one. The factory-consistency argument is real but weaker here than D6, and EADOS itself does not follow the root layout — it consolidates under `.eados-core/` for this same reason |
| A2 | **Move everything, including `.github/` and `package.json`** | Not available. Workflows outside `.github/workflows/` never execute, and the failure is silent; npm will not resolve a package manifest elsewhere. An ADR cannot override another system's requirements |
| A3 | **Change the EADOS templates instead, so every generated project gets this shape** | A much larger decision with a blast radius across every project the factory produces, and it belongs to the factory's own RFC process — not to a side effect of one project's preference. If the shape proves right here, that is the evidence to bring upstream |
| A4 | **Fold the move into the bootstrap commit** | Rejected on auditability. Committing the render as generated and then moving it makes the divergence a visible, reviewable diff with a one-file answer to "why does this repo not look like every other EADOS project" |

## Consequences

**Easier.** The product is one directory: `.eadros-core/` is what `upgrade` migrates, what a
consumer ignores with a single line, and what the item-1.10 post-install assertion checks. The
root reads as governance plus platform requirements, nothing else. The repo's own shape now
demonstrates the containment property D6 asserts, instead of contradicting it.

**Harder.** This repository no longer looks like a repository EADOS generates, so an agent's
transferred mental model is wrong by one level of nesting — which is what AGENTS.md §4 and §5
now state explicitly. Paths in prose across the docs tree need care during the move, and the
lint's two-root split is a permanent (small) complication.

**Not affected.** The npm tarball's contents are governed by `package.json` `files` and the
export map (roadmap item 9.1), not by this layout; installation ergonomics change only through
that item. Re-rendering is not a concern: EADOS
[ADR-0003](../../../.eados-core/docs/adr/0003-generated-repos-are-self-governing.md) rejects
re-rendering a generated repository, so the move will not be undone by the factory.

**Follow-up.** Roadmap item 1.6 (the ADR recording D6 and the concrete internal layout) now has
this ADR as its layout half; the internal organization of `.eadros-core/src/` remains its work.
